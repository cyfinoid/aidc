# Changelog

All notable changes to aidc are tracked here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); the project does not yet cut tagged releases, so all entries live under **Unreleased** until the first tag.

## [Unreleased]

### Added

- **`aidc opencode-web` — opencode's "desktop feeling" in the container (issue #5).** New command runs opencode's browser UI (`opencode web`) inside the container and publishes it on the **host loopback** (`http://127.0.0.1:4096/`, `--port N` or `AIDC_OPENCODE_WEB_PORT` to change), so a host browser drives an agent living in the reproducible container while the LAN never sees it — opencode binds `0.0.0.0` *inside* the container, but the host publish is `127.0.0.1`-only. Reuses the gated compose-override pattern (new `compose.opencode-web.yaml`, active only when `AIDC_OPENCODE_WEB=1`). Auth is **on by default**: a random `OPENCODE_SERVER_PASSWORD` is generated, delivered by env-key reference (never on argv), and printed; `--no-auth` disables it (loopback-safe only), `--username` sets the basic-auth user. Opting in (re)creates the container to attach the port; a later plain `aidc <tool>` recreates it back without it. Documented in `docs/security.md`; covered by `tests/opencode-web.test.sh` and a new case in `tests/compose-file-args.test.sh`.
- **Shared base image + thin per-project layer (smaller disk, faster fresh builds).** The image is split: a shared `aidc-base:<hash>` (OS, uv/Python, the pinned scanners, pmg, and the coding agents) is built **once** and reused, and each project's image is a thin `FROM aidc-base` layer carrying only its detected toolchains and project-setup. The base tag is content-hashed on `Dockerfile.base` + the `AIDC_AGENTS` selection, so template or agent-set changes rebuild it transparently; pin a custom base with `AIDC_BASE_IMAGE=<tag>` in `.ai-container/project.env`. N projects now cost roughly one base plus small deltas instead of N full images. Ports community PR #18 (issue #7).
- **Shared read-only toolchain volume + `aidc tools`.** Go, Rust, and the JDK (plus `gosec`/`cargo-audit`) move out of every project image into **one** read-only Docker volume (`aidc_toolchains`) mounted at `/opt/toolchains`, populated from per-language store images. It fills automatically for detected go/rust/java toolchains on `aidc up`, or manually via new `aidc tools install [go|rust|java|all]` / `aidc tools status`. Read-only so agents can't tamper with the shared toolchain; revoke a bad one once with `docker volume rm aidc_toolchains` and repopulate. The volume is declared `external` so a per-project `aidc destroy` never removes it. Ports community PR #20 (issue #9). Covered by `tests/toolchain-volume.test.sh`.
- **`AIDC_AGENTS` — opt-in coding agents (smaller images).** The five coding agents (claude, codex, opencode, cursor-agent, grok) are no longer all baked into every image (~1 GB of binaries). `aidc <tool>` seeds the build with just that agent on a first build; set `AIDC_AGENTS=claude,codex` (comma-separated) in `.ai-container/project.env` to pin a set, or `all` for every agent (the back-compat default for a plain `aidc up`). Version pins and the fetch-to-file (never piped) install contract are unchanged — only the selection is conditional. Adding a different agent later needs `aidc rebuild` (the existing image fast-starts without it). Ports community PR #15 (issue #8). Covered by `tests/agents-opt-in.test.sh`.
- **CI image-size budget + `aidc status --global` image footprint.** New `.github/workflows/image-size.yml` builds the Dockerfile template with a representative `go,node,python` toolchain set on every PR, posts the resulting image size as a PR comment, and warns past a 6 GB soft ceiling (informational, non-blocking). `aidc status --global` now shows each project's on-disk **image** size alongside the container disk/cpu/mem. Ports community PR #19 (issue #12).
- **`aidc --debug` execution tracing.** A global `aidc --debug <command>` flag (or `AIDC_DEBUG=1`) turns on shell xtrace with a `file:line` `PS4` prefix plus a few `aidc::debug` breadcrumbs, so you can see exactly where a run stalls — most usefully the macOS Keychain OAuth-token read (which blocks on a GUI access-approval prompt on first use) and the first container build. Secret values (the OAuth token and profile API keys) are suppressed from the trace via a new `aidc::secret_begin`/`aidc::secret_end` guard wrapped around every spot the token/profile secrets are read, exported, sourced, or piped. Covered by `tests/debug-flag.test.sh` (includes a token-does-not-leak-under-xtrace assertion).
- **`aidc init -f/--force` to adopt a non-empty repo.** `aidc init` still refuses by default when the target already has a file at an aidc-managed path (so it never clobbers your work silently), but `-f`/`--force` now overwrites those managed files with the current templates and continues, printing a one-line warning naming the workspace. The flag works before or after the optional `[path]`; unknown init flags are rejected with the valid set. Covered by `tests/init-force.test.sh`.
- **Agent-native guardrails: Stop-hook scan enforcement, MCP posture, `aidc insights` (roadmap step 12).** The "run `aidc-scan` before done" guardrail is now **mechanical** for Claude Code: bootstrap seeds a Stop hook (scaffolded `.devcontainer/scripts/aidc-scan-hook.sh`) that blocks finishing while findings above LOW exist in the changed files, feeding the findings back to the agent. Fails open on any scanner/infrastructure error (never wedges the agent), debounces already-clean trees, honors `stop_hook_active` (no block loops), and is opt-out via `AIDC_ENFORCE_SCAN_HOOK=0` (removes the hook on next start; user hooks always preserved). The seeded Claude settings also pin `enableAllProjectMcpServers: false` when absent, so project `.mcp.json` servers keep requiring explicit approval (MCP-as-supply-chain documented in `docs/security.md`). New `aidc insights [--since DATE]`: offline summary of synced Claude sessions (counts, top projects) and scan-hook outcomes (clean/blocked/errors, logged to `.ai-container/scan-hook.log`). Coverage matrix documented: Claude Code enforced; codex/opencode/grok prose-only. Covered by `tests/scan-hook.test.sh` and `tests/insights.test.sh`.
- **CLI polish: completions, better errors, troubleshooting/uninstall docs, honest Linux story (roadmap step 10).** Shell completions for bash and zsh (`completions/`, linked by `install.sh`; command/flag tables drift-guarded against the dispatcher by a test). Unknown commands now suggest close matches and point at `aidc help`/`aidc doctor`; "never initialized" (`run 'aidc init'`) and "corrupt project.env" (restore/backup guidance) are now distinct errors; flag errors name the valid flags. `aidc sync-sessions` defaults to `all` agents (was `claude` only — partial syncs surprised people). New `docs/troubleshooting.md` (symptom → cause → fix, cross-referenced with doctor) and `docs/uninstall.md` (per-project + host-wide removal); `docs/install.md` and the README replace "macOS-only" with a real platform matrix (Linux host: experimental, CI-exercised, no Keychain/clipboard). Covered by `tests/cli-errors.test.sh` (includes a dead-link check over README + docs).
- **`aidc scan` — one command, the right scanners (roadmap step 9).** New scaffolded `.devcontainer/scripts/aidc-scan.sh` (symlinked to `aidc-scan` on the container PATH by bootstrap; `aidc scan` on the host) runs the correct scanner subset for what changed: semgrep (WARNING+) and gitleaks always; shellcheck/bandit/gosec/cargo-audit/bundle-audit/npm-audit when matching files are in scope; vet + the SBOM/license gate only when dependency manifests or the LICENSE changed. Scopes: changed-vs-HEAD (default), `--staged`, `--all`, or explicit paths; `--json` for tooling. Missing scanners are skipped, never fatal; findings above LOW exit 1. The seeded CLAUDE.md/AGENTS.md guardrails now say "run `aidc-scan`" instead of listing five manual scanner invocations, and the changelog/session-log requirements scale with change size (trivial changes exempt; the never-dismiss-findings rule stays non-negotiable). Covered by `tests/aidc-scan.test.sh`; dogfooded on this very change set.
- **`aidc upgrade` — visible, backed-up scaffold updates (roadmap step 8).** Brings an existing project's aidc-owned files up to the running aidc's templates: shows a unified diff per file (`--dry-run`/`--diff` to preview), asks before applying (`-y` to skip; refuses without `-y` on non-interactive stdin), backs up every rewritten file to `.ai-container/backup/<timestamp>/`, re-merges only the managed block in `CLAUDE.md`/`AGENTS.md`, never touches user-owned files (`project-setup.sh`, `license-matrix.tsv`, changelogs, `logs/`, your `project.env` settings), and updates the version stamp in place. Covered by `tests/upgrade.test.sh` and an e2e round-trip.
- **`aidc doctor` and `aidc update` (roadmap step 7).** `doctor` runs read-only OK/WARN/FAIL checks with fix-it hints — host side: git, docker CLI + daemon, `~/.local/bin` on PATH, checkout freshness vs `origin/main` (as of last fetch), Keychain token presence (never printing token material; informational on non-macOS); project side: `project.env` parses, scaffold-version stamp vs current aidc (suggests `aidc upgrade`), container state, firewall posture, isolate-vm prerequisites (limactl/firecracker). Exits non-zero only on genuine FAILs. `update` does an ff-only `git pull` in the aidc checkout (refusing politely on divergence or non-checkout installs), re-runs `install.sh`, and reports old → new version. Covered by `tests/doctor.test.sh` and `tests/update.test.sh`; doctor smoke-asserted on both e2e legs.
- **`aidc version` and tag-driven releases (roadmap step 6).** `aidc version` prints the version plus the git short-sha when run from a checkout. New `.github/workflows/release.yml` fires on `v*` tags: asserts the tag matches `AIDC_VERSION` in `lib/aidc.sh` and that `CHANGELOG.md` has the matching section, then creates the GitHub Release with that section as the body (via the runner's `gh` — no third-party release action). Procedure in `docs/releasing.md`. The `AIDC_VERSION` stamped into each project's `project.env` is now documented as the scaffolded-by version that `aidc upgrade` will compare against.
- **Claude OAuth token now delivered via tmpfs file, not env passthrough (roadmap step 5).** The token travels over the exec's stdin into a `0600` file on `/dev/shm`, is imported into the agent's environment inside the container, and the file is deleted at launch — it no longer appears in `docker` exec metadata or any argv. `AIDC_TOKEN_DELIVERY=env` restores the legacy `-e` passthrough (also the automatic fallback if file delivery fails). Claude profile env files are now **required** to be `0600` at the moment of use (hard error with the exact `chmod` fix; `--list-profiles` still only warns), profile-sourced secrets are scrubbed from aidc's environment after the agent exits, generated profile examples are seeded `0600`, and the template-merge/strip helpers create their temp files next to the target with cleanup on failure. Covered by `tests/token-delivery.test.sh`.

- **Egress firewall hardening — opt-in users only; default stays open (roadmap step 4).** For projects that enable `AIDC_ENABLE_EGRESS_FIREWALL=1`: IPv6 egress is now default-denied (the allowlist is IPv4-only, so v6 previously bypassed the firewall entirely); allowlisted hostnames are re-resolved every `AIDC_FIREWALL_REFRESH_SECONDS` (default 300, `0` disables) with an atomic ipset swap, so CDN/IP rotation no longer strands allowed hosts (events log to `/var/log/aidc-firewall.log`, manual `init-firewall.sh refresh` supported); port-53 egress is pinned to the resolvers in `/etc/resolv.conf`. `aidc status` now shows the firewall posture passively (`off (open network, default)` — the open default is by design, no nagging). The allowlist-file format, IPv6/DNS/DoH semantics, and refresh knob are documented in `docs/security.md`. Covered by `tests/init-firewall.test.sh`.
- **Compose-level container hardening, freedom-preserving defaults (roadmap step 3).** The container no longer carries `NET_ADMIN`/`NET_RAW` unconditionally — those capabilities move to a `compose.firewall.yaml` override that aidc applies only when `AIDC_ENABLE_EGRESS_FIREWALL=1` (default containers run with Docker's standard capability set; sudo/ping unaffected). A `pids_limit` fork-bomb guard (default 4096, `AIDC_PIDS_LIMIT`) plus `AIDC_MEM_LIMIT`/`AIDC_CPU_LIMIT` knobs (unlimited by default) land in the base compose file. Opt-in `AIDC_NO_NEW_PRIVILEGES=1` applies a `compose.hardened.yaml` override (`no-new-privileges` — documented trade-off: disables in-container sudo; auto-skipped with a warning when combined with the firewall, whose init needs runtime sudo). Documented in `docs/security.md` § Container hardening; covered by `tests/compose-file-args.test.sh` and a new compose-posture assertion in the e2e workflow.
- **Every image installer pinned and checksum-verified (roadmap step 2).** All nine previously-unpinned `curl | sh` installers are gone: `pmg`, `trufflehog`, `rtk`, `syft`, and `grype` now install as versioned GitHub release artifacts verified against per-arch SHA256s recorded as Dockerfile `ARG`s (a mismatch fails the build, via the new in-image `aidc-fetch-verified` helper); `git-delta`, `vet`, and `gitleaks` — already version-pinned — gain the same checksum verification; the coding agents (`claude`, `codex`, `opencode`, `grok`) are version-pinned through their vendors' installers, fetched-to-file and never piped. New `scripts/update-pins.sh` refreshes every pin from the vendors' latest releases (`--write` applies). The `sbom.yml` CI jobs and the scaffolded `github-sbom.yml.tmpl` install syft/grype from the same pinned artifacts, and a new `.github/scripts/check-image-pins.sh` CI step asserts each tool inside the built image reports its pinned version. Documented exceptions (cursor — no vendor pin; grok — no vendor checksums; rustup; apt/GPG) in `docs/security.md` § Image supply chain. Covered by `tests/update-pins.test.sh` and `tests/check-image-pins.test.sh`.
- **CI safety net (roadmap step 1).** New `.github/scripts/validate-scaffold.sh` validates everything `aidc init` scaffolds (shell syntax + shellcheck, `project.env` under `set -u`, `devcontainer.json` JSON, `docker compose config` render, `docker build --check` lint) and runs in the e2e workflow after the init scaffold; a new destroy→re-init lifecycle e2e step proves `aidc destroy -f --purge-scaffold --purge-worktree` removes every managed path (and nothing user-owned), leaves no docker volumes, and that re-init reproduces the scaffold byte-for-byte; `sbom.yml` gains an `image-scan` job that builds aidc's own devcontainer image (buildx layer cache) and scans it with grype (report-only initially); new `scorecard.yml` runs OpenSSF Scorecard weekly + on main pushes. Covered by `tests/validate-scaffold.test.sh`.
- **Usability & security roadmap (plan series).** A full-project review produced a 12-step, dependency-ordered improvement roadmap under `plans/roadmap-*.md`: a master overview (`roadmap-00-overview.md`) plus one plan per step — CI safety net, installer pinning, compose hardening, firewall hardening (IPv6/DNS/DoH), token-handling polish, versioning & releases, `aidc doctor`/`update`, `aidc upgrade` (scaffold delivery), `aidc scan` + right-sized guardrails, CLI/docs polish, `lib/aidc.sh` module split, and agent-native (hook-based) guardrail enforcement. Plans only — no behavior change.
- **SBOM generation, license-conflict checks, and CI-agnostic automation.** New `scripts/ci/` scripts generate a code-level SBOM in **both** CycloneDX and SPDX (`sbom-code.sh`), a build-time SBOM from a built image when `AIDC_IMAGE_REF` is set (`sbom-image.sh`), a code-vs-build component diff (`sbom-diff.sh`), and a license-conflict gate that flags dependencies whose license conflicts with the project's own license per a tunable `license-matrix.tsv` (`license-check.sh`) — all orchestrated by `sbom-all.sh`. The scripts are plain bash, env-configured, exit-code-driven, and CI-provider-agnostic (GitHub, Jenkins, GitLab, …); a reference `.github/workflows/sbom.yml` plus a scaffolded `templates/ci/github-sbom.yml.tmpl` show the thin-caller pattern. Exposed as `aidc sbom` and `aidc licenses` (warns locally, `--fail` gates CI), scaffolded into every project via `aidc init`, and documented in `docs/security.md`. `syft` and `grype` are now **always-on** in the image (previously opt-in via `AIDC_SECURITY_TOOLS`). Covered by `tests/{license-resolve,license-check,sbom-diff}.test.sh`.
- **On-demand Claude OAuth token from the macOS Keychain.** `aidc claude` now reads `CLAUDE_CODE_OAUTH_TOKEN` straight from the Keychain (service `claude-code-oauth-token`, your `$USER` account) when it isn't already in the environment, so the token no longer has to be exported into every shell via `~/.zshrc`. An existing env var still wins (back-compat); override the service name or disable the lookup with `AIDC_CLAUDE_OAUTH_KEYCHAIN_SERVICE` (set empty to disable); no-op on hosts without `security`. Dropping `CLAUDE_CODE_OAUTH_TOKEN` from `AIDC_PASSTHROUGH_ENV_KEYS` (per-project via `.ai-container/project.env`) disables both forwarding and the Keychain lookup for that container. Covered by `tests/resolve-oauth-token.test.sh`.
- **Automatic session sync.** In-container agent transcripts now sync to the host on container start (down→up transition), agent exit, `aidc down`, and `aidc destroy` (synced before `-v` removes the volumes), so `/insights` stays current without a manual `aidc sync-sessions`. The start sync is the recovery path for ungraceful exits (crash / `docker kill`) the on-exit hooks can't cover. Toggle with `AIDC_AUTO_SYNC_SESSIONS` host-wide in `~/.config/aidc/config.env` or per project in `.ai-container/project.env` (per-folder overrides global). The agent's exit code is preserved across the post-run sync.
- **Host-wide config file.** New `~/.config/aidc/config.env` holds universal aidc defaults for every project; `.ai-container/project.env` is sourced after it and overrides per folder. Seeded (fully commented) on first run.
- **`aidc rescan` command.** Re-detects project languages and rebuilds so a repo that started empty (or single-language) picks up the matching toolchains and security scanners once code lands. Prints detected vs. effective (overridden) toolchains before building.
- **`shell` toolchain → shellcheck.** `aidc::detect_toolchains` now detects shell scripts (any `*.sh` file, or an extensionless executable with a shell shebang such as `bin/aidc`) and installs `shellcheck` via a new `shell)` arm in the Dockerfile toolchain block.
- **Project documentation seeds.** `aidc init` now seeds `CHANGELOG.md`, `DETAILED_CHANGELOG.md`, and `logs/README.md` into each project once (never overwritten, and intentionally not git-excluded so they are committed). The scaffolded `CLAUDE.md`/`AGENTS.md` guidance gains **Testing & coverage**, **Documentation & changelog**, **Documentation requirements**, and **Session log convention** sections, plus a `shellcheck` line in the security guardrails.
- **Grok Build agent.** `aidc grok` launches xAI's Grok Build CLI inside the container, with a `grok_home` named volume (`~/.grok`), a read-only `/host-seed/grok` seed mount, `sync_grok` seeding in `bootstrap-state.sh`, and `aidc sync-config`/`sync-sessions` support. Grok reads the same generated `AGENTS.md`.
- **GPL-3.0 license.** `LICENSE` at repo root.
- **Vulnerability disclosure policy.** `SECURITY.md` documents scope, reporting channels, and timelines.
- **Shellcheck CI.** `.github/workflows/shellcheck.yml` lints `bin/aidc`, `install.sh`, `lib/aidc.sh`, and `templates/**/*.sh`, plus syntax-checks the Python clipboard server.
- **Split docs.** `HOW_TO_USE.md` broken into `docs/install.md`, `docs/claude-profiles.md`, `docs/security.md`, and `docs/clipboard-bridge.md` for easier linking and discoverability. README rewritten as a true landing page with quick-start, status, and prereqs upfront.
- **Security guardrails — always-on scanners.** `semgrep` (SAST), `gitleaks` and `trufflehog` (secrets) are now baked into every aidc image.
- **Per-toolchain security linters.** When aidc detects a language toolchain, it now also installs the standard linter for that language: `gosec` (Go), `bandit` (Python), `cargo-audit` (Rust), `bundler-audit` (Ruby). Node uses the built-in `npm audit`; Java and PHP rely on semgrep.
- **`AIDC_SECURITY_TOOLS` build arg.** Opt-in heavier tooling per project via `.ai-container/project.env`. Supported: `grype`, `syft`, `checkov`, `bandit`. Mirrors the `AIDC_TOOLCHAINS` pattern; unknown values warn and skip.
- **Agent-enforced guardrails.** `AGENTS.md.tmpl` and `CLAUDE.md.tmpl` now ship a "Security guardrails (non-negotiable)" block inside the aidc-managed marker. Instructs agents to run the relevant scanners on every code change and fix findings above LOW before declaring work complete. User content outside the markers is preserved on scaffold refresh.
- **`aidc status` command.** Per-folder view: container state (running/stopped/not-created) with disk, CPU, memory, PIDs, uptime, plus a config & mounts section listing bind sources (with empty-placeholder annotation) and named volumes.
- **`aidc status --global` command.** Fleet view: every aidc container on the host with workspace path, disk, CPU, memory, PIDs, started/exited timestamp, and a totals line. Filters by `^aidc_` compose project label so non-aidc containers are excluded. Batches `docker container ls --size` and `docker stats --no-stream` for one fork per call instead of N.
- **Local-model Claude profiles.** `localhost.env.example` (targets `host.docker.internal:PORT` for a server on this Mac) and `localnetwork.env.example` (Tailscale MagicDNS / `100.x.y.z` peer; copy to `localnetwork-<engine>.env` for multiple peers).
- **Firewall: Tailscale CGNAT egress.** `init-firewall.sh` and template now permit all-port egress to `100.64.0.0/10`, so tailnet peers stay reachable when `AIDC_ENABLE_EGRESS_FIREWALL=1`.
- **Firewall: `semgrep.dev` in default allowlist.** Needed for `semgrep scan --config auto` rule fetch when the firewall is on.

### Changed

- **`AIDC_AGENTS` now defaults to all agents (opt-in slimming), not the tool you first run.** Because the shared base image (issue #7) amortizes the agents across every project, baking in all five costs the per-project image nothing — so `aidc <tool>` no longer seeds `AIDC_AGENTS` from the invoked tool (which produced fragmented single-agent bases and "missing agent" surprises when switching tools). Set `AIDC_AGENTS` explicitly in `.ai-container/project.env` to build a slim base variant. Supersedes the Wave-2 seed-from-tool behavior.
- **`aidc up` and the agent commands skip the rebuild when the image already exists (fast path).** Routine `aidc up`/`aidc claude`/… used to run `docker compose up -d --build` every time, paying the multi-minute image build (or at least its cache check) on every start. They now build **only when the image is missing** and otherwise start the container directly; `aidc rebuild`/`aidc rescan` still force a full build. `AIDC_NO_BUILD=1` (in `.ai-container/project.env`) forbids implicit builds entirely — `aidc up` then fails fast if the image is missing instead of building it. Ports community PR #14 (issue #13). Covered by `tests/compose-up.test.sh`.
- **Slimmer base image: Node and `build-essential` are no longer unconditional.** `build-essential` and Node 22 were baked into every base image even for projects that used neither. They now install on demand: Node from the nodesource apt repo when the `node` toolchain is detected (or pinned via `AIDC_TOOLCHAINS=node`), and `build-essential` only for the Rust toolchain arm (which needs a C linker). The coding agents are native binaries with no Node dependency, so nothing else regresses. Ports community PR #17 (issue #11).
- **Scaffolded CI scripts are namespaced `scripts/ci/aidc-*.sh`.** The six SBOM/license scripts `aidc init` writes into a project (`lib-common.sh`, `sbom-code.sh`, `sbom-image.sh`, `sbom-diff.sh`, `license-check.sh`, `sbom-all.sh`) are now `aidc-lib-common.sh`, `aidc-sbom-code.sh`, … `aidc-sbom-all.sh` so they no longer collide with a project's own `scripts/ci/` helpers — the un-prefixed names are common enough that `aidc init`/`aidc claude` on such a repo aborted with "refusing to overwrite existing file". Existing aidc projects pick up the renamed files (and are left with the old copies to delete) on the next `aidc upgrade`. All cross-references — the scripts' `source` lines, `aidc sbom`/`aidc licenses`, `aidc-scan`, the reference `sbom.yml`/`github-sbom.yml.tmpl`, and `docs/security.md` — were updated in lockstep.
- **`lib/aidc.sh` split into modules (roadmap step 11).** The ~2,900-line monolith is now a thin entry point (guard + module loading + dispatcher) over eight single-purpose modules under `lib/aidc/`: `common` (constants + helpers), `config`, `profiles`, `scaffold`, `vm`, `runtime`, `sync`, `status`. Pure mechanical move — all 131 function bodies verified byte-identical, full test suite unchanged and green. Layering is CI-enforced by `.github/scripts/check-module-deps.sh` (modules never source shell code; no duplicate definitions; entry point loads each module exactly once). This also delivers the Phase-0 groundwork of the Apple-`container` runtime plan.
- **Implicit commands no longer rewrite scaffold files.** `aidc up` / `rebuild` / the agent commands used to silently re-copy every managed file from the current templates on each run — clobbering local edits to e.g. the Dockerfile. They now only *create missing* files and print a one-line notice when the scaffold is out of date; rewrites happen exclusively through the explicit paths: `aidc upgrade` (diff + backup) and `aidc init`. Template fixes therefore reach existing projects via `aidc upgrade` instead of invisibly on the next `up`.
- **Coding agents now install as native prebuilt binaries.** `claude`, `codex`, and `opencode` switched from a root `npm install -g` to each vendor's native `curl | sh` installer (into `~/.local/bin`), dropping the Node runtime dependency for the agents and shrinking the npm supply-chain surface. Removes the only build step that ran package-manager installs *before* `pmg setup install`.
- **pmg wired in before any user-level install.** `pmg setup install` is now the first `USER vscode` build step. Interception is documented as riding on the `~/.pmg/bin` PATH shims (first on `ENV PATH`) rather than the rc-file aliases pmg also writes — build `RUN` steps and exec'd agents never source rc files. `docs/security.md` now describes the shared-credentials seed-mount/env-passthrough matrix.
- **Pinned `gitleaks` and `vet` versions** in `templates/devcontainer/Dockerfile.tmpl` (`v8.30.1` and `v1.17.3` respectively). Defaults were `latest`, which resolved at build time and defeated the surrounding base-image SHA pin. Repin instructions are in the Dockerfile.
- **README** and the docs/ tree brought into sync with the above. README's command list includes `aidc status`, `aidc down`, `aidc destroy`, `aidc exec`, and `aidc sync-sessions`. `docs/security.md` covers the scanners, supply-chain guardrails, and egress firewall; `docs/claude-profiles.md` covers the local-model profiles (`localhost.env.example`, `localnetwork.env.example`).

- **VM Claude hooks are now rtk-only.** The host-seed `settings.json` carries hooks for host-only tools (`gryph`, and `cot` on a hard-coded macOS path) that are pointless or broken inside the container. `bootstrap-state.sh` now strips just those entries on every `sync_claude` (preserving rtk and any user hooks; self-heals volumes seeded by an older bootstrap), and `install_agent_hooks` wires only `rtk init --global --auto-patch --hook-only` (non-interactive; installs just the hook without re-writing `CLAUDE.md`/`RTK.md`). In-container session transcripts already auto-sync to the host on start/exit, so agent observability stays host-side.

- **`aidc init` adopts a repo that already ships `.devcontainer`/`.cursor` instead of refusing.** When a managed file already exists under `.devcontainer/` or `.cursor/`, `aidc init` now moves that whole tree aside to `<top>.aidc-backup[.N]` (git-excluded, restorable by hand with the printed `mv` hint) and scaffolds its own — no `--force` needed for the common "project already has a devcontainer" case (issue #6). A genuine collision on any *other* managed path (e.g. a project's own `scripts/ci/aidc-*.sh`) still hard-stops rather than silently overwriting. Ports community PR #21. Covered by `tests/init-force.test.sh`.
- **Smaller images: build caches no longer bake into image layers.** The `Dockerfile.tmpl` base and per-toolchain installs now keep transient caches out of the final image — apt archives cleaned (`apt-get clean` + `/var/cache/apt/archives`), uv installs use a BuildKit `--mount=type=cache` for the base Python/semgrep steps and `uv cache clean` after per-project bandit/checkov, Go installs use throwaway `GOPATH`/`GOCACHE` removed after `go install`, Rust routes `CARGO_TARGET_DIR` to `/tmp` and drops the cargo registry/git caches, and Ruby clears the gem cache. All version/SHA pins are unchanged. Ports community PR #16.

### Fixed

- **`aidc opencode` now works — the binary is on PATH.** opencode's installer hard-codes `$HOME/.opencode/bin` and `--no-modify-path` leaves it off PATH, so `aidc opencode` failed with `executable file not found`. The base image now symlinks it into `~/.local/bin` (which is on PATH), like the other agents.
- **Switching the agent set no longer leaves a stale image.** With the shared base, the per-project (thin) image is `FROM aidc-base:<hash>`; the fast path used to start an existing thin image even when the base had changed (e.g. a different `AIDC_AGENTS` selection or an edited base template), so newly-selected agents were missing. The thin image now records its base (an `aidc.base` label) and rebuilds when it differs from the current base tag.
- **Version parsing survived the module split.** `aidc update`'s post-pull version report and the release workflow's tag check read `AIDC_VERSION` from `lib/aidc.sh`, but the split moved the definition to `lib/aidc/common.sh` — both now read the right file. Bundled with a version bump to **0.2.0** so existing projects show as stale and prompt `aidc upgrade`.
- **Synced agent transcripts now reference host paths, not the container mount.** Agent transcripts record absolute paths from inside the container, where the repo is bind-mounted at `/workspace`. Copied to the host verbatim, those `/workspace/...` paths pointed nowhere. `aidc sync-sessions` (and the automatic sync) now rewrites the in-container mount root to the real host workspace path across the synced `*.json`/`*.jsonl` files, so the transcripts reference paths that exist on the host. No-op when the host workspace already is `/workspace`. Ports community PR #23 (issue #22). Covered by `tests/sync-sessions.test.sh`.
- **`aidc-scan` now reliably on PATH inside the container for every command.** The `aidc-scan` shim is a symlink created by `bootstrap-state.sh init`, which runs asynchronously and only at container (re)creation — so a shell/agent could start before it existed (first-run race), and a container reused from before the scaffold gained `aidc-scan.sh` never got the link at all (leaving `aidc-scan: command not found`, and the Stop-hook scan guardrail silently no-op). `ensure_container_running` — the chokepoint every container-entering command shares (`aidc shell`/`exec`/`claude`/`codex`/`opencode`/`grok`/`cursor-agent`/`sbom`/`scan`/`licenses`) — now re-asserts the symlink synchronously on the host (idempotent `ln -sf`, non-fatal), so the guardrail shim is always present. Covered by `tests/scan-link.test.sh`.

- **Sourcing `project.env` no longer clobbers the running aidc version.** `project.env` carries `AIDC_VERSION` as the scaffolded-by *stamp*; `aidc::load_project_env` used to let it overwrite the live version variable, making every stamp-vs-current comparison (doctor, upgrade, staleness notice) compare the stamp against itself. The live version is now restored after sourcing.
- **Permission checks were silently broken on Linux hosts.** `aidc::file_permissions` probed the BSD `stat -f` form first; GNU stat treats `-f` as "filesystem status" and exits 0 with multi-line junk, so the octal-mode fallback never ran and profile-permission warnings could never fire on Linux. The GNU form is now probed first and the result validated as octal on both platforms.
- **RTK install path.** Dockerfile previously set `RTK_INSTALL_DIR=/usr/local/bin` on the wrong side of the pipe (`VAR=val cmd1 | cmd2` scopes `VAR` to `cmd1`), so the installer fell back to `$HOME/.local/bin` while running as root — the binary landed in `/root/.local/bin/rtk` and was invisible to the `vscode` user. Env var moved onto the `sh` side of the pipe.

### Removed

- **AWS Bedrock and Google Vertex support.** `/host-auth/aws` and `/host-auth/gcloud` bind mounts dropped. `AIDC_AWS_SOURCE`, `AIDC_GCLOUD_SOURCE`, `bedrock.env.example`, and `vertex.env.example` removed. AWS- and Google-specific keys (`AWS_PROFILE`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_DEFAULT_REGION`, `ANTHROPIC_VERTEX_PROJECT_ID`, `CLOUD_ML_REGION`, `GOOGLE_APPLICATION_CREDENTIALS`, `GOOGLE_CLOUD_PROJECT`) dropped from `AIDC_PASSTHROUGH_ENV_KEYS`.

- **gryph removed from the image.** SafeDep's `gryph` agent-audit layer is no longer installed (Dockerfile) or hooked (`gryph install` dropped from `bootstrap-state.sh`); host-side hooks for it are stripped from the seeded `settings.json`. `cot` was never in the image (its hook command pointed at a macOS-only binary path) and is likewise stripped. Agent observability is host-side now that sessions auto-sync on container start and exit.
